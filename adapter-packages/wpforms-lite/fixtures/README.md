# Native WPForms authoring fixtures

`native-authoring.json` contains synthetic exercise content written by official
WPForms Lite **2.0.1.1**, whose exact ZIP URL and SHA-256 are in the capsule's
artifact lock. It contains no real submissions, credentials or personal data.
The older 2.0.0.4 exercise pin was moved byte-for-byte from the shared platform
fragment into this capsule when WPForms gained a package owner. It is retained
for historical shared exercises, not newly claimed as an admitted or tested
refusal boundary.
The `origins` entries identify the retained private command stdout records and
their SHA-256 values; these are provenance notes, not a sealed evidence bundle.

The authoring and admin observations ran against engine source `59d9bc4e`.
The literal-notification observation ran against `86f7f891`. All three retained
records were admitted through their command readers after the native pairs
were destroyed. Those observations are historical writer evidence, not a native
conformance run of this new capsule.

- `authoring-*`: exact `post_content` bytes after native form add/update,
  duplicate and template add. The absent, integer and string self-ID variants
  are intentional. Fields carry form-local IDs and limits, not post references.
- `qr-*`: decoded native bodies after real admin initialization, nonce-backed
  settings requests and native QR sanitization. The retained record held JSON
  objects, so these fixture strings are **re-encoded decoded snapshots**, not
  purported original storage bytes. The custom-logo case is Lite-persisted
  paid-feature residue, not proof of paid UI or QR generation support.
- `literal-notification`: exact body after native form update persisted the
  named routing/display values. This is not mail delivery evidence.
- `settings`: the complete native validation-save result, including the
  previously saved general controls and target-local installation/cloud keys.

Package tests use the actual capsule policy with shared capture, compiler,
reference, URL, mixed-option and sidebar machinery. The body replay test has an
independent expected-value transform limited to these measured coordinates.
Its target body codec is not native plugin execution or a full Apply test.
Hostile mutations and embedding/widget fixtures are explicitly synthetic
regression inputs. They do not claim a successful submission, target render,
location rebuild, deployment, lifecycle or cross-plugin scenario.

The package now owns a `capture-plan` conformance entry, native API seed,
source observation and independent host admission. The host compares complete
canonical form bodies plus both embed codecs, and admits full native output
through the shared private transport reader. Its offline probe exercises actual
PostCapture and hostile transport controls; those synthetic controls are not
proof that the new native workflow has run. The target `check.sh` intentionally
refuses until real round-trip evidence replaces the source-only boundary.
